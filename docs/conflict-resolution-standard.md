# Korea Inside Conflict Resolution Standard

## 목적

충돌 상황에서
항상 같은 우선순위로 판단한다.

------------------------------------------------

실행 권한

------------------------------------------------

1. 사용자의 현재 직접 지시

2. 사용자가 승인한 개별 Codex 작업 지시문 또는 Implementation Contract

3. Root `AGENTS.md`의 범위·보호·승인·Git 규칙

4. 관련 전문 기준 문서

5. 페이지별 스펙과 구현 참고자료

최신 인계문, TODO, ROADMAP, 과거 기록은 그 자체로 실행 권한을 부여하지 않는다.

------------------------------------------------

현재 상태와 맥락 출처

------------------------------------------------

1. 실제 저장소 또는 운영 화면에서 재확인한 현재 상태

2. 사용자가 지정한 최신 인계문

3. 현재 조사자료·공식자료·측정자료

4. 과거 인계문·Decision Log·Project Memory·과거 기록

최신 인계문은 현재 상태, 완료사항, 다음 작업 맥락의 기준이지만, 사용자의 실행 승인 없이 새 작업을 자동 시작하게 하지 않는다.

최신 인계문에 다음 작업이 적혀 있어도 사용자 승인 전에는 후보 상태다.

실제 Git 또는 운영 상태와 인계문이 다르면 실제 상태를 재확인하고 차이를 보고한다.

최신 인계문이 명시되지 않았으면 과거 보고서나 기록을 임의로 최신 인계문으로 지정하지 않는다.

과거 인계문은 현재 실행 권한이 아니다.

구현이 쉽다는 이유로 실행 권한이나 확인된 현재 상태를 변경하지 않는다.

------------------------------------------------

권한 해석 규칙

------------------------------------------------

문서 간 충돌 시
더 넓은 원칙보다
현재 사용자 명시 지시,
Root `AGENTS.md`,
승인된 작업 범위를 우선한다.

어떤 문서도
사용자 명시 승인 없이
파일 생성, 수정, 삭제, 이동, 이름 변경,
리팩토링, 포맷팅, stage, commit, push를
허용하지 않는다.

"좋아", "진행", "다음" 같은 표현은
현재 대화에서 승인된 범위 안에서만 해석한다.
보호된 작업은
사용자의 현재 명시 지시와 `AGENTS.md`를 먼저 확인한다.

TODO와 ROADMAP은 후보와 장기 방향 문서이며 실행 승인이 아니다.

과거 인계문의 다음 작업, Git 상태, 승인 상태, Codex 지시문은 현재 작업으로 재실행하지 않는다.

------------------------------------------------

대표 충돌 사례

------------------------------------------------

SEO vs UX

→ 사용자 이해를 우선하면서 SEO 손실을 최소화한다.

Design vs Accuracy

→ 정확성을 우선한다.

AI 제안 vs 확정 결정

→ 확정 결정을 따른다.

새 기능 vs 기존 구조

→ 기존 구조 재사용을 우선 검토한다.

속도 vs 품질

→ 품질을 우선한다.

실물 사진 vs AI 이미지

→ 실물 정확성이 중요한 경우 사용자 제공 실물 사진을 우선한다.

------------------------------------------------

판단 절차

------------------------------------------------

1. 충돌 내용 정의

2. 영향 범위 분석

3. 현재 사용자 명시 지시와 승인된 작업 범위 확인

4. 우선순위 적용

5. 대안 비교

6. 권장안 제시

7. 사용자 명시 승인

8. 구현

------------------------------------------------

예외 규칙

------------------------------------------------

긴급 오류 수정도
사용자 명시 승인과 `AGENTS.md` 범위 통제 안에서만
간소화 절차를 적용할 수 있다.

단,
사후 변경 기록은
사용자가 승인한 범위 안에서만 남긴다.

------------------------------------------------

최종 원칙

------------------------------------------------

충돌은

AI가 임의로 해결하지 않는다.

현재 사용자 명시 지시,
Root `AGENTS.md`,
승인된 작업 범위를 확인하고

우선순위를 적용하고

사용자의 명시 승인을 받는다.
